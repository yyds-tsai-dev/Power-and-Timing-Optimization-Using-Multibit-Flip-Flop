## 對規則設計的觀察(矩陣完整版;供共同討論)

1. **cross-MBFF 在網表 A 炸門檻(tc1 +0.69%、hc01 +1.21%)——全域開 cross
   被否決,gate 紀律立功**。機制假說:網表 A 的 FF cell 大(2b dQpd +4.49、
   pin offset 尺度大),slot 移動帶真實時序風險,而 DP cross 移動仍走舊
   1-hop 定價(呼叫面契約確認未切 oracle)→ 錯價被接受。網表 B(dQpd
   ~0.0002)slot 移動幾乎免費,所以 cross 全贏。
   ⇒ **cross 的規則特徵 = 庫的 slot 時序代價**(如 `dQpd(2b)` 或
   cell 幾何尺度,輸入可導出!):dQpd 小 → 開,大 → 關。
2. **CCDOWN 全案不炸門檻**(最壞 hc01 +0.24%),效果量 ∝ TNS 佔比
   (tc2 14.5%→−2.15%,hc02 22.7%→−1.00%,其餘 ≤4%→|0.24%| 內)。
   ⇒ 候選規則:`TNS_share > ~5%` 時開(run-time 一次 oracle 呼叫可測),
   或直接全域開並接受 0.2% 級的網表 A 尾巴——需 server A 一起裁。
3. **hc02 疊加爆炸(+5.0pp)仍是獨有**;網表 A 的疊加反而比 cross 單獨
   溫和(tc1 +0.16% < +0.69%)——CCDOWN 改變 banking 後 cross 的錯價
   面縮小。交互不可由單特徵預測,建議 v3 只收 CCDOWN(規則式)+
   cross(dQpd 條件式),疊加暫不進 unified。
4. β 單獨不是好軸(tc2/hc03 同 β=400,響應差 700×);
   **TNS 佔比(CCDOWN 軸)× dQpd 尺度(cross 軸)** 是目前最乾淨的二維規則。
