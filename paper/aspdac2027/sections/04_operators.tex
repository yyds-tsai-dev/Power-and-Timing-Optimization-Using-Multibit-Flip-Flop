The oracle of Section~\ref{sec:oracle} turns refinement into a pricing problem: it quotes any move's exact official-cost change before commit. Three move classes are priced exactly: bit re-pairing, structural rebanking, and bin-density eviction. Two positional operators, relocation and critical-pair swap, come from the reference flow. The framework of Section~\ref{sec:framework} interleaves all five; Figure~\ref{fig:operators} sketches these moves.

The three exactly-priced classes share one contract. The engine screens each candidate with a side-effect-free delta, re-prices it exactly against the committed state at apply time, and accepts only if the full weighted delta $\alpha\,\Delta\tns + \beta\,\Delta P + \gamma\,\Delta A + \lambda\,\Delta V$ is negative. Committed sequences therefore decrease the official cost monotonically. The positional operators are narrower: they accept on the exact $\tns$ delta at fixed power and area, without pricing the bin term, so $V$ can drift during relocation. The closing density stage re-prices every remaining violation.

\subsection{Batch Bit Re-Pairing}\label{sec:bitrepair}

The finest-grained moves exchange bits between two multi-bit cells or permute bit-to-slot assignments within one cell (Fig.~\ref{fig:operators}a). The search is batched best-improvement local search, in the spirit of multi-move-per-round scheduling methods~\cite{congram2002dynasearch} and batched placement refinement~\cite{lin2020abcdplace,pan2005fastdp}. Each round enumerates the best swap per cell in a candidate neighborhood, then commits many improving swaps together. Unlike dynasearch proper, it needs no independence structure between moves; each commit is re-priced exactly (below). Screening touches no shared mutable state, so threads price disjoint candidate lists in parallel against a frozen snapshot of the committed placement.

Exact pricing changes what a batch may contain. Conventional batched local search commits only conflict-disjoint candidates, because overlapping timing cones invalidate screened gains. Here each survivor is re-quoted against the committed state just before apply, so a stale gain can only cause a rejection, never a bad commit. The inherited flow's disjoint batching committed roughly $9\%$ of improving candidates per round (152 of 1{,}703 on one hidden case). Dropping the disjointness filter commits every candidate still improving at apply time, an order-of-magnitude throughput gain at identical safety.

Intra-cell slot permutation complements inter-cell exchange. The evaluator prices each sink pin's displacement individually, so permuting which bit occupies which slot changes timing cost without moving the cell; the same delta evaluator prices these moves in the same batches.

Incremental engines converge to local optimality only over candidates they have seen. Periodic full rescans re-enumerate the whole move space and reseed the queue. Between rescans the engine drains cheap dirty-set candidates; each rescan certifies that no improving move was orphaned by earlier commits. The invariants of Sec.~\ref{sec:oracle:validation} check the engine's exactness continuously.

\subsection{Oracle-Guided Structural Rebanking}\label{sec:rebank}

Structural rebanking changes the banking solution after legalization, merging $2{\times}2\mathrm{b}{\to}4\mathrm{b}$ and $4{\times}1\mathrm{b}{\to}4\mathrm{b}$ (Fig.~\ref{fig:operators}b). Candidates come from each cell's same-clock $k$-nearest neighbors, so enumeration stays linear in design size.

Each candidate passes through two phases. A parallel screening phase prices the merge with the group-move oracle at a centroid estimate, on the full objective $\alpha\,\Delta\tns + \beta\,\Delta P + \gamma\,\Delta A + \lambda\,\Delta V$. Power, area, and density deltas are exact from the cell library and bin table; the timing delta assumes the merged cell lands at the candidates' centroid. Screening is side-effect free, so all candidates are priced concurrently. An exact phase then processes survivors in best-first order of screened gain. Each merge is staged rather than applied directly (Fig.~\ref{fig:commit_lifecycle}): mutations are deferred, a legal site is found for the merged cell, and the oracle re-prices the move there; a negative exact delta commits the staged state, and rollback otherwise restores wiring, pin mapping, and placement. Acceptance is strictly monotone, with a patience cutoff.

The same move class cascades under one-hop proxy pricing (Sec.~\ref{sec:background}). Under exact pricing it descends strictly monotonically; on one hidden case each $2{\times}2\mathrm{b}{\to}4\mathrm{b}$ merge alone is worth $-3{,}000$ weighted power-and-area units. The accept pricing and the staged, rollback-safe commits make the difference; Sec.~\ref{sec:ablation} separates the two contributions experimentally.

\subsection{Density-Term Pricing}\label{sec:density}

The density penalty $\lambda \cdot V$ counts bins whose utilization exceeds the limit (Fig.~\ref{fig:operators}d). Density is classically shaped during global placement~\cite{lu2015eplace,chen2008ntuplace3}. Prior refinement operators in this flow never priced the term, so none could trade timing against it. We price it directly alongside exact timing. For each violating bin, an eviction chain relocates flip-flops to legal sites outside it. The chain is priced as a unit, $\alpha \sum \Delta\tns + \lambda\,\Delta V$, and committed only if the total is negative; otherwise every eviction is reverted. Chain-level commit-or-revert matters: a violation clears only when the bin drops below the limit, so partial evictions pay timing cost for no penalty reduction.

\subsection{Interleaved Anytime Framework}\label{sec:framework}

The operators run as interleaved rounds: relocation, critical-pair swap, bit re-pairing, and structural rebanking, repeated twice, with density repair closing the schedule. Both inherited positional operators stay as move generators; the oracle re-prices them. Timing-driven relocation moves a flip-flop to a legalized site near its slack-weighted driver centroid (Fig.~\ref{fig:operators}c). It accepts only on exact $\tns$ improvement at fixed power and area; the closing density stage handles the bin term. Critical-pair swap exchanges two same-footprint cells, leaving power, area, and legality unchanged, so acceptance reduces to the sign of the exact timing delta. Neither operator is new; the oracle of Section~\ref{sec:oracle} now quotes their accepts instead of a one-hop proxy.

Interleaving pays because merges expose new re-pairing opportunities and vice versa. On one hidden case the interleaved schedule beat a single pass of the same operators by $185$K weighted cost units. Each operator exits its round early once it converges, returning unused budget to the schedule. Structural commits are monotone in the official cost and the density stage closes the schedule, so the framework is anytime in practice. Interrupting it at any point yields a legal solution; in all recorded runs the official score descends monotonically across stage boundaries (Fig.~\ref{fig:anytime}).

One repair to the inherited flow determines the move space of all operators. The flow tested a per-cell boolean as a placement-liveness predicate for refinement candidates. Auditing its writers showed the flag is a work-queue marker for the banking stage: clustering clears it, only banking's commit paths set it, and cells placed by the final legalizer keep a stale value forever. On one hidden case the flag silently excluded 2{,}024 of 6{,}309 physical flip-flops ($32\%$) from every refinement operator. The excluded set held all 2{,}000 two-bit cells, the entire two-bit exchange space of Section~\ref{sec:bitrepair}. We replace every flag test with membership in the placement map, the structure the solution writer and legality checkers treat as ground truth. Refinement then covers the complete move space by construction.
